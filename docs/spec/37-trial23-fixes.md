# 37. 23 回目の試行で見つかった問題の修正（M29）

## 背景

22 回目と 23 回目の試行（[36-trial22-fixes.md](36-trial22-fixes.md)）で、AI は 2 回続けて、仕分けを設定する手段が無いことを挙げた。22 回目はサイエンスの仕分けのために設備を物理的に作り直した。23 回目は石炭のベルトに鉄板が混ざり、取り除く仕組みを作り直した。Factorio 2.0 では、燃料式のものを含むすべてのインサーターがフィルターを 5 つまで持てる。スプリッターも研究なしで優先度とフィルターを持てる。

| 区分 | 問題 | 原因 |
| --- | --- | --- |
| BS | インサーターに運ぶ品を指定できない | フィルターを設定するツールが無い |
| BT | スプリッターの優先度とフィルターを設定できない | 設定するツールが無い |
| — | 研究の待ちが最長 50 秒で、呼び出しが増える | 多くのクライアントの 60 秒の時間切れに合わせた上限なので、今回は変えない |
| — | 電力網や燃料の流れを遠くまでたどる診断が欲しい | 周囲の外の情報になり、不変条件 5 に関わるので、今回は扱わない |
| — | 設置の届く距離とキャラクターとの衝突で失敗する | まとめて置く前の確認は `check_placement` と `check_line` で足りるか、次の試行で見る |

## BS. インサーターのフィルター

- 新しいツール `set_inserter_filter(target_ref, items, mode)` を加える。`items` はアイテム名の一覧で 0 個以上 5 個以下、重複を許さない。`mode` は `whitelist`（既定）または `blacklist` とする。
- 対象は、自勢力の、観察済みで手の届く範囲にある `inserter` 型の設備で、フィルターの枠を持つものに限る。手の届く範囲と所属勢力の検査は `rotate_entity` と同じとする。それ以外は `invalid_target` とする。
- `items` が空でないとき、フィルターを使う設定にし、枠 1 から順に設定して残りの枠を空にする。`items` が空のときは、フィルターを使わない設定にし、すべての枠を空にする。
- 存在しないアイテム名は `invalid_input` とし、何も変えない。
- 結果は `name`、`use_filters`、`mode`、`filters`（名前の一覧）、`position` を返す。
- `get_entity_inventory` がインサーターを読むときは、フィルターを使っていれば `filters` と `filter_mode` を加える。
- アイテムを増やさず、設備の設定だけを変えるので、不変条件 2 と 3 は変わらない。

## BT. スプリッターの設定

- 新しいツール `set_splitter(target_ref, input_priority, output_priority, filter)` を加える。どの引数も省略でき、省略したものは変えない。すべて省略したときは `invalid_input` とする。
- `input_priority` と `output_priority` は `left`、`none`、`right` のいずれかで、左右はベルトの進む向きから見る。
- `filter` はアイテム名で、空文字列はフィルターを外す。フィルターを付け、出力の優先度が `none` のままになるときは、ゲームの画面と同じく `left` にして、結果の `hint` で知らせる。
- 対象は、自勢力の、観察済みで手の届く範囲にある `splitter` 型の設備に限る。検査は BS と同じとする。
- 結果は `name`、`input_priority`、`output_priority`、`filter`（無ければ省く）、`position` を返す。
- `observe_nearby` は、スプリッターの設定が既定と違うときに、`input_priority`、`output_priority`、`filter` を返す。`compact` のときも残す。
