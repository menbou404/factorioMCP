# 42. 28 回目の試行で見つかった問題の修正（M34）

## 背景

28 回目の試行（[41-trial27-fixes.md](41-trial27-fixes.md)）で、AI はシード 55555 のマップでも、燃料も含めて手で入れない条件を守って目標を達成した。AI は次の問題を挙げた。

| 区分 | 問題 | 原因 |
| --- | --- | --- |
| CD | 組立機の横で歩きが止まり、`blocked` で失敗した（3 回） | 経路探索のキャッシュが、組立機を置く前の経路を返す。その経路は組立機を通り抜けるので、キャラクターは組立機の側面に当たって止まる。止まったあとの探索し直しでも、同じ経路が返る |
| CE | ベルトの角を作るのに、`place_line` のあとで最後のベルトを回す必要がある（ベルトの回転は 5 回） | `place_line` は、すべてのベルトを線の向きに置く |
| — | 研究の待ちが最長 50 秒で、呼び出しが増える | 6 回目の指摘である。多くのクライアントの 60 秒の時間切れに合わせた上限なので、今回も変えない |

CD の例：393 手目の `move_to` は、(8.79, 59.64) から (32, 91) へ歩き始め、(13.10, 60.38) で止まった。そこは、306 手目に置いた組立機 (14.5, 60.5) の西の側面である。

試行の途中の自動セーブで同じ歩きを再現すると、経路の点は (13.5, 60.5)、(14.5, 60.5) と組立機の中を通った。キャッシュを使わない探索に変えると、経路は組立機の南を回り、歩きはゴールに着いた。

CE の例：504 手目に西向きの線を (14.5, 78.5) まで置いた。505 手目に、そこから北へ続くベルトを置いた。507 手目に `rotate_entity` で (14.5, 78.5) のベルトを北向きにして、角をつないだ。

## CD. 新しい経路で歩く

- `move_to` の経路探索は、キャッシュを使わない。置いたばかりの設備も避けた経路で歩く。
- 歩きが止まって探索し直すときも、同じくキャッシュを使わない。
- ゲームのマップ設定は、30 タイル以上の経路をキャッシュに残す。何もない地面で 60 タイルの経路を一度歩き、その真ん中に組立機を置いてもう一度歩くと、キャッシュを使う探索では `blocked` で失敗し、使わない探索では着いた。40 タイルでは、どちらも着いた。統合試験は 60 タイルの経路で確かめる。

## CE. ベルトの角を作る

- `place_line` と `check_line` に `end_direction`（0、4、8、12）を加える。指定すると、線の最後のベルトだけをその向きで置く。
- 次の線へ曲がる角を、1 回の呼び出しで作れる。たとえば西向きの線の `end_direction` を 0（北）にすると、最後のベルトが北を向く。
- 線の向きと逆の向きは、`invalid_input` とする。ベルト以外（パイプなど）に指定したときも、`invalid_input` とする。
- 最後の場所に同じ向きのベルトがすでにあれば、`already_present` に数える。違う向きなら、今までどおり `different_direction` で止まる。
- 結果に `end_direction` を加える。

## 効果の確認

M34 のあとの試行も、シード 123 以外のマップで行う。
