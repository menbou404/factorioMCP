# 19. 6 回目の試行で見つかった問題の修正（M11）

## 背景

2026-11-04 の 6 回目の自律試行（[18-trial5-fixes.md](18-trial5-fixes.md)）で、AI が新しい問題を挙げた。この文書は、その原因と修正、または修正しない理由を記録する。

| 区分 | 問題 | 原因 |
| --- | --- | --- |
| L | 半径 4 の絞り込んだ観察の後、その前の観察で見えていた場所へのラボの設置が `not_visible` になった | 設置の可否を、直前の 1 回の観察の範囲だけで判定している |
| M | `mine_entity` に `count: 160` を渡して入力エラーになった。採掘中の設置が `action_conflict` になったが、ヒントは歩行・採掘・製作の衝突しか説明していなかった | ツールの説明に、数量の上限（1〜100）と、即時の操作も歩行・採掘の完了を待つことが書かれていない |
| N | 鉱石の観察で数百の資源エンティティが返った。資源の集計だけがほしい | `include_resources = false` で個々の資源を省いても集計（`resources`）は返るが、説明に書かれていない |
| N | 木に手が届かず採掘が失敗した。観察に距離と届く距離がほしい | 観察結果に、キャラクターからの距離と、操作ごとの届く距離を含めていない |

## L. 直近の観察の範囲

設置に必要な「観察済み」の判定を、直前の 1 回ではなく、60 秒以内の直近の観察すべての範囲で行う。

- Mod は、観察ごとに中心・半径・面・時刻を記録し、直近 8 回まで保持する。60 秒を過ぎたものは判定に使わない。
- 設置位置が、そのどれかの範囲（中心からの距離が半径以内）に入っていれば、観察済みとみなす。
- `not_visible` の `detail.observed` は、これまでどおり直前の観察を示す。
- 観察で付ける `target_ref` の期限と検証は変わらない。

## M. 入力の上限と衝突の説明

- `mine_entity`・`craft`・`transfer_item` の説明に、`count` が 1〜100 であることを書く。
- `action_conflict` のヒントに、設置・受け渡し・回転・レシピの設定も、実行中の歩行・採掘があると `action_conflict` になることを書く。製作の実行中は行える。

## N. 観察の距離と資源の集計

- `observe_nearby` の各エンティティに `distance`（キャラクターの中心から、エンティティの中心までの距離）を加える。
- `observe_nearby` の結果に `reach` を加える。`build`（設置の届く距離）、`interact`（受け渡し・回転などの届く距離）、`mine_resource`（資源・木・岩の採掘の届く距離）の 3 つを持つ。資源・木・岩は、中心ではなく当たり判定の縁までの距離で判定されるので、`distance` が少し大きくても届く場合があることを説明に書く。
- `observe_nearby` の説明に、`include_resources = false` のときも資源の集計（`resources`：資源ごとのタイル数・総量・範囲）は返ることを書く。
