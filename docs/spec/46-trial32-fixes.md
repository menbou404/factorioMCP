# 46. 32 回目の試行で見つかった問題の修正（M38）

## 背景

32 回目の試行（[45-trial31-fixes.md](45-trial31-fixes.md)）で、AI はシード 31415 のマップでも、燃料も含めて手で入れない条件を守って目標を達成した。AI が挙げた問題と、呼び出しの記録から分かったことは次のとおりである。

| 区分 | 問題 | 原因 |
| --- | --- | --- |
| CN | ボイラーに燃料を入れるインサーターの置き場所がずれていて、石炭を地面に落としていた | 設置の結果は `pickup_position` と `drop_position` の座標しか返さない。座標の先に設備があるかは、AI が自分で確かめる必要がある |
| CO | 探索済みの地図が示した岸の位置に汲み上げポンプを置けなかった | `nearest_shore` は水に接する水のタイルで、ポンプを置ける位置と向きは確かめていない |
| CP | 歩いてから設置・受け渡し・撤去をする 2 回の呼び出しが多い | `move_to` のすぐ次の呼び出しは、`place_entities` が 34 回、`transfer_item(s)` が 34 回、`mine_entity` と `mine_entities` が 19 回だった。`place_line` 以外は自分で歩かない |
| — | 研究の待ちが最長 50 秒で、呼び出しが増える | 上限は変えない（60 秒で切れるクライアントがあるため） |

CN の例：303 手目で、ボイラー（中心 (48, 0.5)、東向き）の西に置いたインサーターの `drop_position` は (46.7, 0.5) で、ボイラーの外だった。AI は 412 手目でボイラーの燃料切れに気づき、置き直しを 2 回行った。

CO の例：130 手目の `get_explored_map` は岸を (44.5, -5.5) と示したが、132 手目の `check_placement` は `placement_rules` で置けないと返した。AI は `nearby_positions` の候補を使って次の呼び出しで置いた。

## CN. インサーターの受け取り先と渡し先を示す

- インサーターの設置結果、`get_entity_inventory`、`get_entity_inventories` に、受け取り先 `pickup_target` と渡し先 `drop_target` を加える。中身は対象の `target_ref` と名前で、先に設備がないときは返さない。
- 採掘機にも `drop_target` を加える。
- 渡し先に設備がないときは、注意 `no_drop_target` と案内を返す。案内には、品が地面に落ちること、渡し先をこれから置くなら気にしなくてよいことを書く。
- `observe_nearby` では、渡し先のないインサーターと採掘機に `no_drop_target` を付ける。
- 説明文に、設置の結果で渡し先を確かめる使い方を書く。

## CO. 汲み上げポンプを置ける位置を示す

- `observe_nearby` で水を記録するとき、記録した区画の中で汲み上げポンプを置ける位置と向きを 1 つ確かめて覚えておく。
- `get_explored_map` の水には、確かめた位置と向きを `pump_position` として加える。見つからなかったときは返さない。
- 確かめるのは観察した範囲の中だけで、観察していない場所は調べない。
- 説明文に、`pump_position` をそのまま使えることを書く。

## CP. 歩いて届く位置まで近づく

- `place_entities`、`transfer_items`、`mine_entities` に `walk` を加える。既定は `false` で、今までと同じに動く。
- `walk=true` では、項目を並んだ順に処理し、手が届かない項目があれば、届く位置まで歩いてから処理する。歩きは `place_line` の `walk=true` と同じ仕組みを使う。
- `walk=true` の呼び出しは歩き・採掘の枠を使う動作になり、`wait_seconds`（1〜50）と `wait_for_action` で待つ。結果は `walk=false` と同じ形の項目ごとの結果に、歩いた回数を加える。
- 歩いても届かない項目は、その項目の結果を `out_of_range` にして次の項目へ進む。`mine_entities` は今までどおり最初の失敗で止まる。
- `walk` なしで `wait_seconds` を渡したときは `invalid_input` とする。
- 説明文に、離れた場所への設置や受け渡しを 1 回の呼び出しでできることを書く。

## 効果の確認

M38 のあとの試行も、シード 123 以外のマップで行う。

33 回目の試行（2026-11-19、シード 27182、敵なし）でも、燃料を含めて手で入れない条件を守り、`military-2` の研究（赤緑 20 個ずつ）まで終えた。この条件での成功は 14 回目で、初めてのマップでは 12 回目である。

| 項目 | 32 回目（シード 31415） | 33 回目（シード 27182） |
| --- | --- | --- |
| ツール呼び出し | 612 回 | 678 回 |
| エラー | 21 回 | 39 回 |
| `move_to` の次が設置・受け渡し・撤去だった回数 | 87 回 | 26 回 |
| `walk=true` の `place_entities` | — | 47 回 |
| `walk=true` の `transfer_items` | — | 46 回 |
| `walk=true` の `mine_entities` | — | 12 回 |
| `no_drop_target` を含む結果 | — | 21 回 |
| 入力トークン | 2,782 万 | 2,798 万 |
| かかった時間 | 57 分 | 77 分 |
| 最後の研究 | `military-2`（赤緑 20 個ずつ） | `military-2`（赤緑 20 個ずつ） |

- CP：`walk=true` の `place_entities`、`transfer_items`、`mine_entities` は 105 回とも、動作として最後まで終わった。歩いてから設置・受け渡し・撤去をする 2 回の呼び出しが、1 回で済むようになった。
- CO：`get_explored_map` の `pump_position` へ、そのまま汲み上げポンプを置けた。
- CN：`no_drop_target` の注意は 21 回出た。インサーターの結果には、受け取り先と渡し先のベルトや設備が返った。
- マップが違うため、呼び出しの総数と時間は 32 回目と比べられない。エラーが増えたのは、材料不足の `craft`（15 回）と `set_recipe`（5 回）である。
- 手で入れた最後の品は、`logistic-science-pack` の研究完了（666 手目）より前である。
- AI が挙げた残りの問題は [47-trial33-fixes.md](47-trial33-fixes.md) で扱う。
