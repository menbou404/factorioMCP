# 01. 構成と接続

## 構成

```text
AI クライアント ── MCP ──> ローカル MCP サーバー
                             │
                             └── RCON ──> 画面付き Factorio マルチプレイ主催
                                                └── 専用 Mod ──> AI キャラクター
人間 ── Factorio の画面で参加・観察 ────────────────────────┘
```

MCP 接続とゲームへの参加は別である。AI クライアントは MCP サーバーのツールを呼ぶ。人間は Factorio を開いてマルチプレイを主催する。Mod は AI 用キャラクターをゲーム内に生成するので、AI 用の Factorio クライアント接続は初期構成に不要である。

## 起動と終了

1. 対象のセーブで専用 Mod を有効にする。
2. Factorio の画面からマルチプレイを主催する。通常のシングルプレイ起動は初期構成に含めない。
3. プロジェクトの起動スクリプトが Factorio へ `--rcon-bind 127.0.0.1:27015` と専用パスワードを渡す。ゲーム本体の `config/config.ini` は変更しない。画面付きマルチプレイ主催での動作を確認する。
4. ローカル MCP サーバーを起動し、RCON 認証、Mod のバージョン確認、セーブ上の AI キャラクターとの再対応付けを行う。
5. AI クライアントから MCP サーバーに接続する。Mod がキャラクターを 1 体用意する。重複生成はしない。
6. MCP サーバー終了時、Mod のキャラクターはセーブ内に残る。ハートビートが 10 秒間途絶えた進行中の歩行・採掘・製作は停止する。再起動後に再対応付けする。

## RCON の役割

RCON は外部から Factorio にコマンドを送る管理用経路であり、プレイヤー接続ではない。Mod は単一の独自コマンドを登録し、許可された操作だけを受け付ける。応答は RCON を呼び出した相手へ JSON で返す。歩行や採掘のように時間がかかる操作は、開始時に操作 ID を返し、後続の照会で状態を取得する。

## 安全境界

- RCON の接続先は `127.0.0.1`。パスワードをソースコード、セーブ、ログ、AI 向けツール結果に記録しない。
- MCP サーバーは任意のコマンド実行や `/c` をツールとして提供しない。RCON パスワードの保有者には強い管理権限があるため、MCP の入力は Mod の許可済み操作に変換する。
- Mod も操作名、引数型、対象範囲、上限値を検証する。生の Lua 文字列を評価しない。
- RCON が切れてもゲームを改変しない。再接続後、未確定の操作を照会して二重実行を防ぐ。

## 対応範囲と根拠

初期構成は同じ PC 上の画面付きマルチプレイ主催を対象とする。後日の専用 Factorio サーバー構成では、Factorio 側の起動方法と RCON 設定だけを替え、MCP ツールと Mod 内のゲーム操作は維持する。

参照: [画面付き主催時のローカル RCON](https://forums.factorio.com/viewtopic.php?p=201757)、[専用サーバーの RCON 設定](https://wiki.factorio.com/Command_line_parameters)、[独自コマンド](https://lua-api.factorio.com/latest/classes/LuaCommandProcessor.html)、[RCON 応答](https://lua-api.factorio.com/latest/classes/LuaRCON.html)。
