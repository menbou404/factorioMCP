# 47. 33 回目の試行で見つかった問題の修正（M39）

## 背景

33 回目の試行（[46-trial32-fixes.md](46-trial32-fixes.md)）で、AI はシード 27182 のマップでも、燃料も含めて手で入れない条件を守って目標を達成した。AI が挙げた問題と、呼び出しの記録から分かったことは次のとおりである。

| 区分 | 問題 | 原因 |
| --- | --- | --- |
| CQ | `place_line` の `walk=true` が、障害のない道でも `stand_position_not_found` で止まった（2 回） | 立つ位置の候補は、観察の範囲（16 タイル）の中しか調べない。列の始まりが遠いと候補が 1 つも見えず、歩き出さずに止まる |
| CR | ベルトを対象に `wait_for_items` で石炭を待ったが、`current` が 0 のままだった | `wait_for_items` は設備のインベントリだけを数える。ベルトにはインベントリがないので、品が流れていても 0 になる |
| CS | 組立機に入れるインサーターが `waiting_for_space_in_destination` で止まり、原因が分からなかった | インサーターの結果は渡し先の名前しか返さない。渡し先の組立機はレシピが決まっていなかったが、それは別に調べないと分からない |
| — | 研究の待ちが最長 50 秒で、呼び出しが増える | 上限は変えない（60 秒で切れるクライアントがあるため） |

CQ の例：400 手目の `place_line` は (-30.5, 58.5) から 32 タイルの列で、キャラクターは始まりから 20 タイル以上離れていた。1 枚も置かずに `stand_position_not_found` を返した。

CS の例：634 手目で、インサーター（548）は `waiting_for_space_in_destination` で、渡し先は組立機（479）だった。同じ呼び出しで読んだ組立機 479 は `no_recipe` だった。

## CQ. 遠い列の始まりへ近づいてから立つ位置を探す

- `place_line` の `walk=true` で、立つ位置の候補が見えないときは、次に置くタイルの近く（手の届く距離）を目指して歩く。着いてから、立つ位置をもう一度探す。
- 近づいたあとも立つ位置が見つからないときは、今までどおり `stand_position_not_found` で止まる。同じタイルで 2 回は近づかない。
- `place_entities`、`transfer_items`、`mine_entities` の `walk=true` と同じ近づき方を使う。

## CR. ベルトの上の品を待つ

- `wait_for_items` の対象がベルト、地下ベルト、分配器のときは、ベルトの上にある品の数を `current` として数える。
- 結果に `belt = true` を加え、ベルトの上の数は流れて変わることを説明文に書く。
- `produced=true` はベルトには使えない。指定したときは `invalid_input` とする。

## CS. インサーターの渡し先の状態を示す

- `get_entity_inventory` と `get_entity_inventories` で、インサーターの `drop_target` に渡し先の状態 `status` を加える。渡し先が材料不足の組立機なら、`missing_ingredients` も加える。
- インサーターが `waiting_for_space_in_destination` のときは案内を返す。案内には、渡し先の状態（レシピがない、出力がいっぱい、持っている品が十分あり別の材料を待っている など）を見るように書く。
- 説明文に、インサーターが止まったときに渡し先の状態を見る使い方を書く。

## 効果の確認

M39 のあとの試行も、シード 123 以外のマップで行う。
