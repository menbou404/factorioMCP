# 15. 自律試行で見つかった問題の修正（M7）

## 背景

2026-11-02 の 2 回目の自律試行（[14-agent-ergonomics.md](14-agent-ergonomics.md)）で、AI が残りの問題を挙げた。この文書は、その問題ごとの原因と修正を記録する。修正は問題ごとに PR を分けて入れ、すべて入った後に同じ条件で 3 回目の試行をする。

| 区分 | 問題 | 原因 |
| --- | --- | --- |
| A | 岩や木の採掘が進まず、約 20 秒後に `blocked` になる | 位置で選択するため、近くの別の木が選ばれた。また、木や岩に届く距離を実際より長く判定していた |
| A | 60 個の採掘が 59 個で `timeout` になる | すべての行動に 120 秒の上限があり、長い採掘が打ち切られた |
| B | `target_ref` と観察が 10 秒で失効し、設置や受け渡しが途中で失敗する | 期限が短い |
| B | 設備ごとの区画名が観察から分からない | 観察結果に区画名を含めていない |
| B | 長い採掘で `wait_for_action` の待ち直しが要る | 待ち時間の上限が 30 秒 |
| C | ボイラーの位置が丸められ、オフショアポンプと接続口がずれた | 設置の事前確認が、丸めた後の位置と接続口の位置を返さない |

## A. 採掘の修正

### 対象の選択

`mine_entity` は、キャラクターの選択を位置ではなく対象のエンティティそのものに合わせる（`LuaControl.selected` に対象を代入する）。位置で選ぶと、選択範囲が重なった別のエンティティ（隣の木など）が選ばれ、採掘状態がすぐに止まる。シード 123 の `big-rock`（53.5, 34.125）で、位置による選択では隣の `tree-02-red` が選ばれて採掘が始まらず、対象を直接選ぶと約 3 秒で石 20 個を得たことを確認した。

- 代入後に選択が対象と一致しない場合は、行動を始めずに `invalid_target`（`detail.reason = "not_selectable"`）を返す。
- 採掘中に選択が対象から外れた場合は、対象を選び直して採掘状態を再設定する。

### 届く距離

木や岩も、届く距離の判定はゲームの `LuaControl.can_reach_entity` に従う。Mod はこれまで、資源以外の対象を手の届く距離（`reach_distance`、10）で判定していた。しかし独立キャラクターでは、木や岩の `can_reach_entity` は資源の採掘距離（`resource_reach_distance`、2.7）を基準に判定され、約 3.9 タイル離れた木でも偽になった。その場合ゲームは採掘状態をすぐに解除するので、行動は 20 秒後に `blocked` で終わっていた。

`mine_entity` は、開始時と採掘中の両方で `can_reach_entity` が偽なら `out_of_range` を返す。`detail` の `reach` は、資源・木・岩では `resource_reach_distance`、それ以外では `reach_distance` とする。

### 採掘の打ち切り

採掘には、全行動に共通の 120 秒の上限を適用しない。代わりに、既存の進捗判定（20 秒間アイテムが増えなければ `blocked`）で止める。`count` の上限は 100 のままなので、採掘時間は対象と数量で決まる有限の長さになる。歩行の上限は変えない。

### 途中までの成果

採掘の行動が失敗・取り消しで終わった場合も、`detail` にそれまでに得た `gained` と現在の `inventory` を含める。たとえば 50 個を指示した岩が 20 個で消えた場合は、`target_gone` と `gained = 20` を返す。

### 試験

- 統合試験の既存の採掘（鉱石・木・石）がそのまま通ること。
- シード 123 の岩で、採掘が `succeeded` になることを手元で確認する（CI の固定セーブには選択範囲が重なる配置がないため）。

## B. 期限と観察の情報

### 期限を 60 秒にする

`target_ref` の有効期限と、設置に必要な観察の鮮度を、10 秒から 60 秒に延ばす。試行では、観察から設置・受け渡しまでの間に移動や確認をはさむと 10 秒を超え、`target_gone` や `not_visible` で失敗した。

期限を延ばしても、行動の時点で Mod が対象の実在・距離・所属勢力・衝突を検証する規則は変わらない。消えた対象には `target_gone`（`reason = "entity_gone"`）を返し、同じ位置の別物を操作しない。設置は、直近の観察範囲の中だけで認める規則も変えない。

### 観察に区画名を含める

`observe_nearby` は、自分の勢力の設備のうち `transfer_item` と `get_entity_inventory` が扱える設備に、`inventory_roles`（その設備で使える区画名の一覧、名前順）を含める。例: 石の炉は `["fuel", "result", "source"]`、ラボは `["input"]`。他の勢力の設備と、受け渡しに対応しない設備には含めない。

### 完了待ちの上限を 50 秒にする

`wait_for_action` の `timeout_seconds` の上限を 30 秒から 50 秒に上げる。既定値は 20 秒のまま変えない。上限を 60 秒にしないのは、MCP クライアントの多くがツール呼び出しの待ち時間を 60 秒に設定しており、それを超えるとクライアント側で失敗するためである。

## C. 設置の事前確認

### 丸めた後の位置

Factorio は、設備の中心を格子に合わせて丸める。幅または高さのタイル数が奇数の辺はタイルの中央（x.5）に、偶数の辺はタイルの境界（整数）に置く。向きが東・西のときは幅と高さを入れ替える。試行では、ボイラー（3×2）を (52, -2.5) に置こうとして (52.5, -2) に置かれ、オフショアポンプとの接続口がずれた。

Mod は、設置の検証・衝突の確認・作成のすべてで、この丸めた位置を使う。`check_placement` は丸めた位置を `position` として返す。`place_entity` が返す `position` と一致する。

### 流体の接続口

`check_placement` と `place_entity` は、流体を扱う設備（パイプ、オフショアポンプ、ボイラー、蒸気機関など）について `fluid_connections` を返す。各要素は次のとおり。

| 項目 | 内容 |
| --- | --- |
| `position` | この設備の側の接続口があるタイルの位置 |
| `target_position` | つなぐ相手の設備（の接続口）が必要な位置 |
| `direction` | 接続口の向き |
| `flow` | `input`、`output`、`input-output` |

`check_placement` は設備の種類の定義と向きから計算する。`place_entity` は作成した設備の実際の接続口を返す。`observe_nearby` は、自分の勢力の流体を扱う設備に、各接続口が相手とつながっているか（`connected`）を加えて返す。

### 設置できない理由の補足

衝突する設備も地形も無いのに設置できない場合（オフショアポンプの取水口が水に面していないなど）は、`blocked` の `detail` に `reason = "placement_rules"` を加える。また、同じ位置で設置できる向きがあれば `valid_directions` として返す。試行では、オフショアポンプの `blocked` に、`blocking` と `tiles` が空の `detail` しか返らず、向きを変えて何度も確認した。
