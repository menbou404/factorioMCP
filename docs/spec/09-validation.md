# 09. 実装順序と受け入れ条件

## 実装前に実機で確定する事項

| ID | 検証 | 合格条件 |
| --- | --- | --- |
| P1 | 利用者の Factorio バージョンと画面付きマルチプレイ主催時のローカル RCON | Mod の独自コマンドに要求を送り、JSON 応答を受け取れる |
| P2 | 未接続プレイヤーに紐付かない `character` の歩行 | 画面で連続歩行が見え、座標変更やテレポートを使わない |
| P3 | 同キャラクターの通常採掘 | 採掘時間、距離、容量を守り、本人の持ち物が増える |
| P4 | 同キャラクターの手作業製作 | 材料が消費され、通常の時間後に本人の持ち物が増える |
| P5 | 材料消費を伴う建設 | ゲームの設置条件を満たす時だけ設備が 1 個増え、本人の持ち物が 1 個減る |
| P6 | 設備とのアイテム移動 | 炉に燃料と鉱石を入れ、完成品を回収でき、合計数量が複製されない |

P1～P3 のいずれかが不成立なら最初の完成単位を達成できない。P4～P6 が不成立なら「工場を建てる」完成条件を達成できない。失敗時は抜け道として無償生成やテレポートを採用せず、成立する操作方法を再検討する。

## 段階

1. **接続**: 画面付きのマルチプレイ主催、Mod、MCP サーバー、RCON の往復を成立させる。
2. **身体**: AI キャラクター 1 体を生成し、セーブ再読み込みで同じ体を再利用する。
3. **歩行と観察**: 周囲を読み、指定地点へ歩き、到着と失敗を区別する。
4. **採掘と持ち物**: 鉄鉱石などを採掘し、本人の持ち物が正しく増える。
5. **製作・建設・受け渡し**: 材料を使って製作・設置し、炉に材料と燃料を入れて完成品を回収する。
6. **工場の実演**: 人間が資材を渡さず、AI が素材収集から始め、燃料式掘削機から石の炉へ鉄鉱石を送り、炉へ燃料を入れる。起動後に AI が鉱石を手で補充せず、鉄板 10 枚以上を生産する。

## 全体の受け入れ条件

- 画面上で AI キャラクターが歩き、採掘し、設備を建てる様子を人間が観察できる。
- AI が得たアイテムは本人のゲーム内インベントリに入り、消費する行動で減る。
- アイテム、設備、研究、位置を無償で得る経路が MCP ツールに存在しない。
- 範囲外や未観察の対象への操作は失敗する。
- 通信切断、要求再送、セーブ再読み込みでアイテムと設備が複製されない。
- 人間の操作キャラクターを Mod が勝手に動かさない。
- 燃料式掘削機と石の炉による鉄板生産設備を AI 単独で建て、起動後に鉱石の手補充なしで鉄板 10 枚以上を生産できる。

## 検証方法

各段階で Factorio 画面での動作と、Mod が返す位置・インベントリ・操作状態を照合する。特に P3～P6 は開始前後のゲーム内数量を記録し、失敗時・キャンセル時・再送時も確認する。公式 API の記述だけで実機合格とみなさない。工場の実演には鉄鉱石と石炭が到達可能な検証用マップを使い、マップ条件を記録する。

## 現在の検証結果

- Factorio 2.0.77 の隔離したヘッドレスマルチプレイ環境で、RCON 応答、独立キャラクターの歩行、通常採掘、手作業製作、アイテム消費を伴う木箱設置、箱との双方向移動、石の炉への木材・鉄鉱石投入、鉄板の回収を確認した。
- `NewGameForMCP` のコピーでも Mod が読み込まれ、セーブ再読み込み後に同じ 1 体の AI キャラクターが維持された。
- 素材不足時は製作と設置が失敗し、同一 `request_id` の再送ではアイテム移動が二重実行されないことを確認した。
- 接続確認が途絶えた長距離移動が約 10 秒後に `connection_lost` で停止したことを確認した。
- 素材だけを配置した隔離された検証用マップで、AI キャラクターの空の持ち物から石・木・石炭・鉄鉱石を集め、炉と燃料式掘削機を製作・設置した。掘削機から炉へ自動供給して鉄板 10 枚を生産し、段階 6 のゲーム内数量条件を満たした。操作順は固定の試験プログラムから Mod/RCON 経由で指示したもので、AI モデルの計画能力の検証ではない。
- 画面付きの主催中に人間が AI の動きを観察する P1・P2 の画面側条件は、利用者の GUI セッションでの検証待ちである。
