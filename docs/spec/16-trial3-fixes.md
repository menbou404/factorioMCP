# 16. 3 回目の試行で見つかった問題の修正（M8）

## 背景

2026-11-03 の 3 回目の自律試行（[15-agent-trial-fixes.md](15-agent-trial-fixes.md)）で、AI が新しい問題を挙げた。この文書は、その原因と修正、または修正しない理由を記録する。修正は区分ごとに PR を分けて入れ、すべて入った後に同じ条件で 4 回目の試行をする。

| 区分 | 問題 | 原因 |
| --- | --- | --- |
| D | 目的地の近く（0.6〜0.9 タイル）で歩行が `running` のまま終わらず、AI が `cancel_action` で止めた（3 回） | 目的地のタイルが障害物で塞がれていると、キャラクターが障害物に沿って左右に小さく動き続ける。位置が毎 tick 少しずつ変わるので、停止の判定（1 tick の移動が 0.1 タイル未満）にかからない |
| E | キャラクター自身が設置場所に立っていると、`blocking` も `tiles` も空の `placement_rules` が返った | 阻害物の一覧からキャラクター自身を除いている |
| E | かまどの設置で、地面のアイテムと一緒に銅鉱石の資源が `blocking` に並んだ | 範囲内のエンティティをすべて並べていて、設備と衝突しない資源も含めている |
| F | 50 個の採掘は 50 秒の待ちを超え、待ち直す間に進み具合が分からない | 実行中の状態に進捗を含めていない |
| F | 研究の完了を待つ手段がなく、`get_research_status` を繰り返し呼んだ | 研究を待つツールがない |

## D. 歩行の到着判定

### 停滞の判定

歩行中、経路の次の点に 3 秒（180 tick）着かない場合も、位置が止まった場合と同じく停滞とみなす。停滞したら経路を引き直し、引き直しが 3 回を超えたら `blocked` で終える。これまでの「1 tick の移動が 0.1 タイル未満の状態が 2 秒続く」判定も残す。

### 目的地が塞がれている場合

経路の点をすべて通り過ぎた後（最後の接近）、目的地までの距離が 1 秒（60 tick）縮まらない（0.05 タイル以上縮まない）場合は、それ以上近づけないとみなす。そのとき、

- 目的地まで 1.5 タイル以内なら、`succeeded` で終える。`detail` に `distance`（目的地までの残りの距離）と `goal_blocked = true` を含める。
- 1.5 タイルより遠ければ、`blocked` で終える。

到着の許容距離は 0.5 タイルのまま変えない。0.5 タイル以内に入った場合の `detail` には `goal_blocked` を含めない。

### 失敗時の情報

歩行が `blocked`・`timeout` で終わった場合は、`detail` に `distance`（目的地までの残りの距離）と `goal`（目的地）を含める。

### 試験

- 統合試験の既存の歩行がそのまま通ること。
- 木の幹の中心を目的地にした歩行が、1.5 タイル以内で `succeeded`（`goal_blocked = true`）になり、10 秒以内に終わること。試行で止まった 3 か所は、いずれも目的地が木の幹の中だった。経路探索は目的地から 1 タイル以内（`request_path` の `radius` の既定値）に着ければ経路を返すので、小さな木では経路が見つかり、幹の手前で止まる。建物の中心のように 1 タイル以内に空きが無い目的地は、従来どおり `path_not_found` になる。
- シード 123 のマップで、試行で止まった目的地 (82, 55) への歩行が、0.73 タイル手前で `goal_blocked` として終わることを手元で確認した（修正前は 27 秒以上 `running` のままだった）。

## E. 設置の阻害情報

### キャラクター自身

設置範囲に自分のキャラクターが重なっている場合は、`blocked` の `detail` に `reason = "character_in_the_way"` を加える。`placement_rules` は、阻害物・地形・キャラクターのどれも無い場合だけに返す。キャラクターを押しのけたり動かしたりはしない（テレポートしない規則のため）。AI は自分で離れてから設置し直す。

### 衝突しないものを並べない

`blocking` には、設置する設備の衝突レイヤーと共通のレイヤーを持つエンティティだけを並べる。資源（鉱石など）は設備と衝突しないので並べない。地面のアイテム（`item-entity`）は衝突するので並べる。

## F. 進捗と研究の待ち

### 実行中の進捗

`get_action_status` と `wait_for_action` は、実行中（`running`）の採掘について `detail` に `gained`（これまでに得た数）と `count`（指示した数）を含める。製作については `count`（指示した数）と `remaining`（まだ完成していない数）を含める。

### 研究の完了待ち

MCP サーバーに `wait_for_research(technology, timeout_seconds)` を加える。`timeout_seconds` は 1〜50 秒、既定値 20 秒。サーバーが `get_research_status` を繰り返し確認し、次のどれかで返す。

- 指定した技術が研究済みになった（`researched = true`）。
- 指定した技術が研究中でなくなった（研究キューから外れた）。`researching = false` を返す。
- 待ち時間を超えた（`timed_out = true`）。

返す内容は `technology`、`researched`、`researching`、`progress`（研究中なら 0〜1）、`timed_out`、`waited_seconds`。Mod の変更は要らない。

## 変えないもの

| 指摘 | 扱い |
| --- | --- |
| 採掘中に設置しようとすると `action_conflict` になる | 1 体につき実行中の操作は 1 つという規則（[08-mcp-interface.md](08-mcp-interface.md)）のまま。設置は採掘の完了後か取り消し後に行う |
| 製作中に別の製作を指示すると `action_conflict` になる | 同上。まとめて作る場合は、完了を待ってから次を指示する |
| 採掘機の出力が地面にこぼれて設置の邪魔になる。生産を止める操作がほしい | ゲームにない操作は加えない。燃料を抜く、採掘機の向きを変える、`mine_entity` で地面のアイテムを拾う、で対処できる |

## 効果の確認（2026-11-04）

D・E・F のマージ後、3 回目と同じ条件（シード 123、平和モード、同じ指示文、`gpt-6.1-sol`）で 4 回目の試行をした。4 回目も目標を達成し、組立機が作った赤サイエンス 10 個で `gun-turret` を研究した。

| 項目 | 3 回目（M8 前） | 4 回目（M8 後） |
| --- | --- | --- |
| ツール呼び出し | 322 回 | 361 回 |
| ツールのエラー | 7 回 | 14 回（うち 6 回は材料不足の `missing_materials`） |
| 歩行の `cancel_action` | 3 回 | 0 回 |
| `placement_rules`（理由不明の設置失敗） | 1 回 | 0 回（`character_in_the_way` が 2 回） |
| 研究の確認 | `get_research_status` 11 回 | `get_research_status` 6 回、`wait_for_research` 6 回 |
| 入力トークン | 約 818 万 | 約 460 万（-44%） |
| 出力トークン | 約 1.1 万 | 約 1.3 万 |
| Codex の 5 時間枠 | 16% | 9% |
| 所要時間 | 20 分 | 21 分 |

M8 で直した問題は再発しなかった。目的地の手前で歩行が止まらない問題は起きず、キャラクター自身が設置場所に立っていた 2 回は `character_in_the_way` が返り、AI はその場から離れて設置し直した。研究の完了は `wait_for_research` で待った。

エラーが増えたのは、材料が足りないまま製作や受け渡しを指示した `missing_materials` が 6 回あったためである。呼び出し回数は 1 割増えたが、入力トークンと Codex の使用量は大きく減った。
