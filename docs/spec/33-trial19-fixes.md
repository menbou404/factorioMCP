# 33. 19 回目の試行で見つかった問題の修正（M25）

## 背景

19 回目の試行（[32-hands-off-automation.md](32-hands-off-automation.md)）で、AI は手運びを禁じた目標を達成した。そのうえで次の問題を挙げた。

| 区分 | 問題 | 原因 |
| --- | --- | --- |
| BH | 観察して採掘もした石炭が、`get_explored_map` に載らなかった | 地図は 8×8 のマス全体が観察の円に入ったときだけ記録する。一部だけ見えたマスの資源は捨てている |
| BI | 操作の開始は `action_id` を返すのに、`get_agent_status` は `action.id` を返す。AI が取り違えて、`action_id` の無い呼び出しをした | 同じ番号に 2 つの名前がある |
| — | 研究を待つ `wait_for_research` を 20 回呼んだ | 待ち時間の上限 50 秒は、MCP クライアントの 60 秒の制限に合わせたものなので変えない |

## BH. 一部だけ見えたマスの資源

- 観察の円に一部だけ入ったマスも、見えた資源を地図に記録する。そのマスには `partial` の印を付ける。
- 同じマスを再び一部だけ観察したときは、見えた資源のタイル数の合計が多い方を残す。マス全体を観察したら、全体の記録で置き換える。
- `resources` の項目のうち、一部だけ見えたマスを含むものに `partial = true` を付ける。タイル数と埋蔵量は見えた分だけである。
- `explored` の数と `frontier` では、一部だけ見えたマスは観察済みに数えない。水、木、岩は、これまでどおりマス全体を観察したときだけ記録する。

## BI. 操作の番号の名前をそろえる

- `get_agent_status` の `action` と `craft_action` に `action_id` を加える。互換のため `id` も残す。

## 次の試行の条件

20 回目からは、`logistic-science-pack` の研究のあとは、燃料も含めて、手で設備に入れることを禁じる。
