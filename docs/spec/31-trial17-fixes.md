# 31. 17 回目の試行で見つかった問題の修正（M23）

## 背景

17 回目の試行（[30-trial16-fixes.md](30-trial16-fixes.md)）で、AI は緑サイエンスの目標を達成した。そのうえで次の問題を挙げた。

| 区分 | 問題 | 原因 |
| --- | --- | --- |
| BC | インサーターの向きが分かりにくかった（向き 0 は北から取り、南へ置く） | 説明に、向きと取る側の関係を書いていない |
| BD | `products_finished` がレシピを変えても続けて数えるので、前のレシピで作った数と混ざった | ゲームの値をそのまま返している |
| BF | 探索で、歩いて観察する呼び出しが多かった。観察済みの範囲の端が分かる地図が欲しい | `get_explored_map` は観察済みの範囲の外枠と資源を返すが、まだ観察していない隣の場所を返さない |
| — | 手の届く距離（10 タイル）をわずかに超えた受け渡しが失敗した | `out_of_range` の詳細に距離と届く距離を返している。`move_to` の `within` で近づけば足りるので、ツールでは扱わない |

## BC. インサーターの向きの説明

- `place_entity`、`place_entities`、`check_placement`、`rotate_entity` の説明に、インサーターの向きと取る側・置く側の関係を書く（向き 0 は北から取って南へ置く。4 は東から取って西へ、8 は南から取って北へ、12 は西から取って東へ置く）。説明の向きは、実際のゲームの値で確かめる。

## BD. レシピを変えてから作った数

- 組立機の中身の結果に、今のレシピに変えてから作った完成品の数 `products_since_recipe` を加える。`set_recipe` でレシピを変えた時点の `products_finished` を記録し、その差を返す。記録が無い設備（AI が `set_recipe` で変えていない設備）では省く。
- `wait_for_items` の `produced` は、これまでどおり待ち始めてからの数で数える。

## BF. 観察済みの範囲の端

- `get_explored_map` に、観察済みの 8×8 のマスに隣り合う、まだ観察していないマスのうち、キャラクターに近いものを `frontier` として返す（最大 `limit` 個、マスの中心の座標と距離）。
- まだ観察していない場所の地形や資源は返さない。AI が知るのは、自分が観察した場所と、その隣がまだ観察されていないことだけである。

## 根拠資料

- [Factorio Runtime API](https://lua-api.factorio.com/latest/index-runtime.html)

## 効果の確認（2026-11-06）

BC・BD・BF のマージ後、同じ目標で 18 回目の試行をした。18 回目も目標を達成し、組立機が作った赤と緑のサイエンスで `military-2` を研究した。緑サイエンスの材料のベルト 20 個とインサーター 20 個も組立機が作り、インサーターで緑サイエンスの組立機へ自動で送った。

| 項目 | 17 回目（M23 前） | 18 回目（M23 後） |
| --- | --- | --- |
| ツール呼び出し | 437 回 | 369 回 |
| ツールのエラー | 12 回 | 3 回 |
| `move_to` の失敗 | 0 回 | 0 回 |
| 入力トークン | 約 983 万 | 約 1,121 万 |
| 所要時間 | 33 分 | 33 分 |

呼び出しとエラーは、これまでの試行で最も少なかった。研究は 98% で一度止まったが、AI は `wait_for_research` の `labs` と `short_science` から、使いかけの赤と緑のサイエンスが別々のラボに分かれていると判断して直した。

### 残っている指摘

18 回目で AI が挙げた次の点は、まだ扱っていない。

- 燃料式掘削機の `check_placement` に、掘った資源を落とす位置（`drop_position`）が無い。最初のチェストを 1 タイルずれた位置に置いた。
- 炉の材料不足の原因（上流の掘削機の燃料切れ）を調べるのに、掘削機を 1 台ずつ見に行く必要があった。
- 17 回目の指摘のうち、手の届く距離をわずかに超えた受け渡しは、`move_to` の `within` で足りるとして扱っていない。
